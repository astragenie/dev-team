## Decisions

### DEC-028: HTML comment fence as canonical marker for build-time injected blocks

**Rationale**: When a build-time render script injects a block into a Markdown file, use an HTML comment fence (BEGIN tag with embedded hash, END tag) as the marker. The hash inside the BEGIN tag makes idempotency trivial (re-running with the same source body produces the same fence content; re-running with drifted source produces a different hash and the regex still matches the old fence for replacement). HTML comments are invisible in rendered Markdown so the marker does not visually pollute the agent prompt. Multiline-regex friendly for both --inject (replace) and --check (extract + compare).

**Consequences**:
- positive: idempotency is byte-exact, not heuristic. md5sum equality across re-runs.
- positive: marker is grep-able for tooling (validate-agents.ts can extract the hash in one regex).
- positive: invisible in rendered Markdown — no visual pollution of agent prompts.
- positive: the hash IS the identity — drift detection trivially compares two strings, no semantic diff needed.
- negative: Markdown renderers that strip HTML comments would lose the marker. Acceptable: agent prompts are consumed by Claude Code plain-text harness, not a Markdown renderer.
- negative: future injectors using a different marker syntax need to register their fence to avoid grep collisions. Cheap to enforce via convention.

## What I would do differently next time

For any new script mixing library exports with a CLI entry point, the isMainEntry guard is the FIRST line written, not the last. Bake into spec-writer anchor template for executable-script deliverables.

For any script that resolves external file paths, write a smoke-run AC that hits the REAL paths before declaring done, separate from the fixture-isolated tests. SLICE-76 namespace-cache bug PASSED all 12 fixture tests but FAILED on first real invocation. The fixture tests are correct; they just do not catch hardcoded-path regressions in the resolution branch.

For Option B / pilot scope slices, the builder needs an explicit DO-NOT-inject-anywhere-but-the-pilot guard at the script entry point. SLICE-76 glob bug could have been caught with an assertion check. Cheap, defensive, makes pilot scopes harder to violate accidentally.
