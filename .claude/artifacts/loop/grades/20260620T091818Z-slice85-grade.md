## Lessons

- **Inline build for additive observability slices is fast.** No subagent dispatch — main thread had full mental model from SLICE-84. Build took ~20min including 4 tests + live smoke. Single inspector review (no Reviewer B since contract was unchanged from SLICE-84).
- **Bundling a prior-slice followup advisory into the next slice keeps backlog small.** Inspector's LOW advisory from SLICE-84 (regex misses `rejected`) shipped as a 1-line edit in this slice — no separate FEAT/SLICE for a 4-character regex change.
- **Inspector's own LOW advisory caught a substring-regex bug in real time.** `/rejected/i` would have matched `not-rejected`. Word-boundary fix shipped as immediate follow-up commit `b820ca3` (1 line, 1 test gap exposed: validation regex needed `/\bfail/i` prefix-only because real artifacts use `failed`, not `fail`). Round-trip cost ~5min.

## Surprises

- Live cost-report after slice-complete had NO `## Agent stats` section. Initially looked like a bug — turned out to be the exact documented fail-safe: `.claude/logs/dispatch-timing.jsonl` doesn't exist in this repo (no slices have ever logged dispatch timing here), aggregator returns empty rows, `collectAgentStatsForRun` returns undefined, conditional spread omits the field, renderer returns []. AC-6 verified live by the absence of the section.

## Followups

- **FEAT-159 SLICE-C** (lead consumption) — only remaining FEAT-159 deliverable. Edits `agents/lead.md` Step 3 to read latest agent-stats artifact. `autonomous_safe: false` — gated on human review.
- **dispatch-timing.jsonl will be populated by future loops** — once a slice runs that hits the dispatch-timing pre-tap hook, the section will start appearing in subsequent cost reports automatically. No further code change needed for that to "turn on".

## What went well

- Slice spec called out the bonus regex fix explicitly → no scope creep surprise at review.
- File LOC budgets all met first try (no compression pass needed).
- 11/11 → 18/18 test gain (new 4 cost-report + 7 registry from parallel SLICE-86 work, all green).

## What went wrong

- First word-boundary regex `/\bfail\b/i` broke AC-T4 because real validation artifacts use `failed` (not `fail`). Caught immediately by re-running tests after the fix. Lesson: validation verb forms vary; use prefix-only `\bfail` for the broad case.

## What I would do differently next time

When a reviewer's LOW advisory has a tight fix radius (single regex / single line), apply + re-test inline before opening the grade rather than letting it land as a separate commit. Saves a ceremony round-trip.
