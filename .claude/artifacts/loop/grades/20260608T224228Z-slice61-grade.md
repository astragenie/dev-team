## Lessons

- The `compute.ts` / thin-wrapper pattern is a model for future I/O-heavy script extractions. Reviewing imports at the end of extraction (verifying zero `fs`/`readline`/`path`/`os` imports) is a good completeness check.
- `tokensFromUsage` was promoted from private to exported without a justification note in the handoff. Any widened public surface should be documented even if no current caller is affected — API surface has memory.
- 38 unit tests covering all 9 extracted functions is the right level of coverage for a compute module with no I/O.
