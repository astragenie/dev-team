## Lessons

- Lazy-import the OTel SDK inside `initBridge()` — disabled path never loads `@opentelemetry/sdk-node` (~10MB module graph). Default-disabled hot path stays ≤50ms p95.
- Two-key opt-in (`cfg.enabled: true` AND `CREW_OTEL_ENABLED=1`) — config alone OR env alone both disable. Audit grep for `enabled: true` catches accidental config defaults; audit grep for `api.anthropic.com` enforces subscription-only constraint.
- `InMemorySpanExporter` from `@opentelemetry/sdk-trace-base` enables full bridge round-trip testing with zero network — CI doesn't need Docker / Langfuse for the automated AC suite.
- Try/catch wrap on every `emit*` — telemetry crash never propagates to Claude. Hooks always exit 0.

## Decisions

### DEC-TBD-1: Telemetry uses lazy OTel SDK import + InMemorySpanExporter for CI

**Rationale**: Two architectural choices that compose. Lazy import of `@opentelemetry/sdk-node` inside `initBridge()` keeps the disabled-default path under the ≤50ms p95 hook latency budget — module graph never loads. `InMemorySpanExporter` for tests means full bridge behavior (config → parse → scrub → span emit → batch processor → exporter) tested without network. Optional Langfuse round-trip (AC-12) marked `validation_skipped: docker_unavailable` for CI hosts without Docker.

**Consequences**:
- positive: zero cold-start cost when telemetry disabled (the default).
- positive: CI passes without Docker, OTLP endpoint, or auth credentials.
- positive: AC-12 round-trip still validates the live path when run manually with Langfuse up.
- negative: lazy import means first telemetry emit pays SDK load latency; mitigated by warming initBridge() at process start when enabled.
