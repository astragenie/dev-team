## Lessons

- Builder context-ceiling not hit on this slice; pure additive scope kept dispatch tight.

## Decisions

### DEC-001: PowerShell automatic variable deny-list pattern

**Rationale**: Naive regex `\$[A-Z_][A-Z0-9_]*` matches PS automatic variables (`$_`, `$HOME`, `$NULL`, `$TRUE`, `$FALSE`, `$LASTEXITCODE`, etc.) that are NOT env-var shape mistakes. Excluding them via explicit deny-set is more honest than tightening the regex.

**Consequences**:
- positive: catches real env-var shape errors without nagging on common PS idioms
- positive: deny-list is editable per shell-environment evolution
- negative: deny-list maintenance — new PS auto-vars need adding manually

## Surprises

- PowerShell automatic-variable count larger than expected (32 documented; $_ + $HOME + $LASTEXITCODE + ~29 others).
- Partial-match bug: `$PSVersionTable` matched only `$PSV` due to lowercase-letter terminator in greedy regex; needed look-ahead guard.

## Followups

- Consider extracting a Bash auto-var deny list if symmetric false positives appear (positional args, special vars).
- Telemetry counting which check fires most often could inform v2 check additions.

## What went well

Pure-check-library + thin-hook shape continues to scale: matches the v0.3.11 cost-hygiene-reread pattern and the later FEAT-032 subagent-return pattern. Cross-platform path detection (POSIX + Windows separators) worked first try thanks to a single regex with `[\\/]` character class. Reviewer caught the PowerShell false-positives before merge, demonstrating the independent review gate's value on a slice the builder reported as "all 14 ACs PASS".

## What went wrong

Builder's initial false-positive surface (`$_` warning on every PowerShell pipeline) would have shipped without the reviewer pass. Spec didn't enumerate PS automatic variables, so builder over-applied the regex. Earlier, more adversarial test cases in the spec would have caught it pre-handoff.

## What I would do differently next time

For env-var-shape-style regex checks, include "false-positive guards" as explicit AC items in the slice spec rather than leaving them to reviewer discovery. The deny-list pattern is reusable — could be extracted to a shared `scripts/lib/shell-env/` library when a 3rd shell check lands.
