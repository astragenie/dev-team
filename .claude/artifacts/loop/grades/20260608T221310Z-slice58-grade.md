## Lessons

- Spec divergence on float rejection slipped through: `validateDays()` accepted `1.5` even though the doc says "positive integer." Pure-function ACs must be verified with a REPL before handoff.
- TDD commit order was not evidenced — single atomic commit hides whether tests were written first. Require a failing-test commit checkpoint even for small slices.
- `process.exit(N)` in entry-point `main()` is borderline vs `process.exitCode` convention — precedent exists, but builder should note the deviation explicitly rather than leaving it for the reviewer.

## What went well

All 8 AC delivered: script, flags (`--older-than`, `--dry-run`, `--repo`), destructive/dry-run modes, age validation, unit tests, manifest validation. 460 tests pass. Lint and typecheck clean on first pass.

## What went wrong

Float validation gap in `validateDays()` — rejected NaN/negative/zero but accepted `1.5`. Spec said "positive integer" but implementation only checked positivity. No reviewer-required followup was addressed before close.

## What I would do differently next time

Write the boundary test (`--older-than 1.5` → reject) alongside the integer boundary tests. Single REPL check of accepted input types before handoff would catch this class of spec divergence immediately.
