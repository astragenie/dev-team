## Lessons

- JSDoc generic parsing issue: `() => string` inside `Array<[unknown, () => string]>` closes the generic angle bracket. Use `function(): string` form instead.
- Wave-based agent delegation for large annotation passes works but agents introduced TS2322 by typing `options = {}` as `{}` (empty object) — overcorrect compared to shape typedefs.
- `.catch(() => null)` needs explicit `/** @returns {null} */` annotation in JSDoc mode when TypeScript can't infer the chain's return type.
- `@param {any}` placed by early wave agents must be audited and replaced with `unknown` on boundary guards.
- `/** @type {Record<string, number>} */` on const objects with string indexing fixes TS7053 cleanly.

## Surprises

- Wave-2 agents typed `options = {}` parameters as `{}` (empty object literal type) causing TS2339 on option property access — required re-annotation with proper shape typedefs.
- `ReturnType<typeof fn>` in JSDoc is a clean pattern for capturing typed array element types without duplicating typedef shapes.

## What went well

## What went wrong

Early wave agents used `{}` as the type for `options = {}` parameters, causing downstream TS2339 errors that required a second pass. Agent-generated annotations need a review pass specifically for `options = {}` patterns.

## What I would do differently next time

Run `npm run typecheck 2>&1 | grep "TS2339"` as an intermediate check after each agent wave to catch `{}` pattern issues early, before proceeding to the next wave.
