# SLICE-12: Artifact-path-only subagent returns — Grade

**Slice:** SLICE-12

## Scores

- architecture_quality: 0.90 — pure check library + thin PostToolUse hook; same shape as preflight + reread hooks (consistent pattern across 3 hooks)
- reliability: 0.85 — exception-safe; tolerant body extraction (content / body / string fallback)
- observability: 0.80 — best-effort event log
- production_readiness: 0.90 — default-on, opt-out via CREW_SUBAGENT_INLINE_THRESHOLD=0
- security: 0.85 — input parsed defensively
- test_confidence: 0.95 — 40 tests including cross-platform path detection (POSIX + Windows separators) + library unit tests
- product_completeness: 0.90 — full spec shipped; minor negative-threshold clamping deferred

## Lessons

- Third instance of the pure-check-library + thin-hook pattern (cost-hygiene reread, preflight-shell, subagent-return). Pattern is established and worth codifying as a skill.
- Builder context-ceiling NOT hit — tight spec + Sonnet model + locator pre-discovery in the dispatch prompt kept work bounded.

## Decisions

### DEC-003: Path regex covers all .claude/artifacts/crew/* subdirs

**Rationale**: Expanded beyond just handoffs/ to include reviews/, validations/, deployments/, runs/, cost/, cost-insights/, agents/. Any artifact-path reference satisfies cost-discipline rule #2 — handoffs/ isn't sacred.

**Consequences**:
- positive: reviewer can return a path to a review-result.md and not trigger the warn
- positive: validator-result paths also recognized
- negative: directory list needs updating if new artifact kinds are added

## Surprises

- PostToolUse Agent payload shape not documented in repo. Builder defaulted to `tool_response.content` (matched Read pattern) and added `tool_response.body` + string fallback for tolerance.
- Reviewer truncated mid-investigation at 46 tool uses — context-ceiling problem with overly-adversarial review prompts; lead recovered with inline review.

## Followups

- Clamp negative threshold values (`CREW_SUBAGENT_INLINE_THRESHOLD=-100` would warn on every body). Minor.
- Document the PostToolUse Agent payload shape in repo if Claude Code maintainers expose it.

## What went well

Builder shipped clean 40-test surface first pass. Cross-platform path detection (POSIX + Windows) worked first try with one regex. UTF-8 byte counting via `Buffer.byteLength` correctly handled non-ASCII content.

## What went wrong

Reviewer dispatch hit context-ceiling on adversarial test cases — too many "would this match X" edge cases inflated tool calls. Inline review by lead was faster + cheaper.

## What I would do differently next time

Trim reviewer dispatch prompts: 5-7 concrete checks instead of 10+ adversarial cases. Adversarial cases belong in tests, not in the review prompt.
