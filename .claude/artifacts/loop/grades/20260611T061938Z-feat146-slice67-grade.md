## Decisions

### DEC-017: Hook flow = exported core (`hooks/lib/<name>.ts`) + thin entry shim

**Rationale**: Each per-tool hook (check-redundant-read, check-subagent-return, record-read-content, preflight-shell) previously required a `node --experimental-strip-types` spawn per test (~120 spawn tests × 0.3–0.6s on Windows). Extracting the flow into a unified core `run<Name>Hook(raw: string, env: NodeJS.ProcessEnv) => Promise<string | null>` lets tests `import` the core and assert in-process. Entry shims keep stdin/stdout/exit semantics byte-identical for the runtime contract.

**Consequences**:
- positive: ~120 spawn tests collapse to in-process imports — large wall-clock lever after WS1 (suite 115.9s → 21.1s).
- positive: `record-read-content` loses its mid-flow `process.exit(0)` (repo rule 6 compliance).
- positive: 469 LOC of spawn-test boilerplate deleted.
- negative: contract drift between core + shim is now possible. Mitigated by ≥1 retained spawn smoke per hook (6 total) + `tests/hook-feature-gating.test.ts` unchanged as the spawn-based runtime-contract proof.
- negative: test helper signatures now type as `NodeJS.ProcessEnv` (includes `undefined`) instead of `Record<string, string>`. Caught + fixed during typecheck.

## Surprises

- Net-negative LOC refactor: +83 / -469. Most of the delete is spawn-test scaffolding, not core logic. Suggests prior spawn harnesses were carrying significant boilerplate per assertion.
- Slice arrived in this session already merged but never closed — `git log` showed `ac1ceae` landed before snapshot regeneration. The loop snapshot's `in-flight FEAT-146 (P2)` line was a stale-state artifact, not real WIP.

## What went well

The contract split (core + shim) is the right shape: tests no longer pay spawn cost, the runtime stays byte-identical, and the 6 retained spawn smokes give a backstop if the core ever drifts from the shim. All 5 ACs hit clean. Lint + typecheck green. The `process.exit(0)` removal in `record-read-content` is a bonus repo-rule-6 fix that fell out of the refactor for free.

## What went wrong

Slice close ceremony was skipped by the prior builder. Work landed mid-flight as a normal commit, but no handoff, no final synthesis, no grade, no cost report, no slice-progress update. Loop snapshot stayed stale (`FEAT-146 in-flight`) for ~24h. Validation gate also unsatisfied — no validation artifact for a test-only refactor where the obvious validation is "run the converted suites + retained spawn smokes" (the bundle shows that did happen — just wasn't written as a validation artifact).

## What I would do differently next time

Treat "builder returns" and "slice closes" as separate events with separate failure modes. A builder that merges + returns success without running `/loop:slice complete` should fail a hygiene check on the lead side — either auto-run close on builder success, or refuse to dispatch the next slice while a previous one is in-progress without slice-start event activity.
