## Lessons

- Extracting provider code into a shared package (gepa-core) surfaced a dead-field defect (`temperature` declared but unused) that did not exist in the pre-extraction code — refactors that widen a public interface can introduce interface-level bugs even when the runtime behavior is unchanged for current callers, because nothing currently exercises the new surface.
- The reviewer explicitly credited the dev-team shim's `GeminiJudge` empty-key guard as the correct choice to *keep* (rather than remove for consistency with gepa-core's native-fetch implementation) because it preserves the existing test contract — a good example of "matching upstream" not automatically being the right call when downstream has a deliberate, tested divergence.

## Surprises

- None beyond the two already-documented findings (temperature dead field, CI-matrix without-sdk cell providing no differentiated coverage).

## Followups

- gepa-core patch 0.3.1: either store+forward `temperature` in `OllamaJudge.evaluate()`'s request body, or remove the field from `OllamaConfig` — reviewer's explicit non-blocking follow-up.
- AC-4 (live baseline) was formally resolved after this review: `validations/20260629T125000Z-ac4-live-baseline-slice107-slice108.md` captures 3 live provider runs (groq, gemini, groq/inspector) once operator API keys became available, closing the deferral as `evidence_captured`.

## What went well

A dedicated security sweep with zero findings, plus explicit verification that the extraction didn't change env-var handling (`check:no-env` exits 0) or silently alter existing behavior beyond the one documented dead-field issue. The reviewer also independently confirmed `claude-p.ts` had zero diff against main, meaning the shim for that provider was deliberately left untouched by the extraction.

## What went wrong

A new interface-level defect (unused `temperature` config field) was introduced by the extraction and shipped without a blocker — acceptable given "no current caller passes this field," but still a real defect in a newly-published package version that external consumers could hit.

## What I would do differently next time

When extracting an interface into a shared package, add a round-trip test per config field (set it, call the underlying API mock, assert it was actually forwarded) — this specific class of defect (accepted-but-dropped config) is easy to miss with only shape/type-level tests.
