## Lessons

- Splitting bundled FEATs at PM-triage time pays off. SLICE-A landed in ~10 min of edit work + a clean gate (616/616, 0 lint, 0 typecheck, 0 format issues). The deferred SLICE-B (new `skills/domain/observability/`) would have ~doubled the blast radius and pushed past the ≤200 skill cap if bundled.
- The grade-template `product_completeness` dimension cleanly captures the SLICE-A-only-of-3 situation (0.65). The other dimensions are full PASS because the work this slice ACTUALLY did is complete and correct.
- Worktree path discipline: when the harness is inside a worktree, every Edit `file_path` must be the worktree absolute path, not the main-repo absolute path. The first round of edits landed in main; reverted via `git checkout --` and re-applied to the worktree. Memory exists for this class of error — add a worktree-path specific entry.

## Decisions

### DEC-018: Defer observability skill — split FEAT-141 into SLICE-A + SLICE-B

**Rationale**: PM-triage scope challenge on FEAT-141 flagged that the third deliverable (new `skills/domain/observability/` skill) is conditionally needed — only when the observability grade dimension slips below the 0.80 floor. Current snapshot has observability AT 0.80 (borderline). Bundling all 3 deliverables would have inflated the slice cost ~2x for content that has no urgency signal yet. SLICE-A ships the two low-risk lenses with measurable routing impact; SLICE-B opens when observability dips.

**Consequences**:
- positive: smaller blast radius, faster review, clean gate pass.
- positive: skill cap headroom preserved (deployment-patterns 130/200, review-gates 105/200).
- positive: deferred work documented as a followup item against a fresh FEAT, not a forgotten obligation inside a closed FEAT.
- negative: FEAT-141's `product_completeness` dimension drops to 0.65 because the FEAT shipped 2 of 3 deliverables. The loop CLI auto-moved FEAT-141 to `done/` on `slice complete` — split FEATs would benefit from a `partial-completion` flag the loop respects.

## Surprises

- Loop CLI `slice complete` moved FEAT-141 to `done/` unconditionally even though the slice file's "Done When" explicitly conditioned the FEAT-move on SLICE-B completion. The CLI doesn't read the "Done When" prose. Followup: file a FEAT for a `feature_close_policy: keep-in-progress-until <other-slice>` frontmatter field on slice files.
- `requires_validation: false` waiver worked cleanly through `slice complete` — validation gate marked `satisfied: true` with reason `explicit-waiver: slice frontmatter requires_validation: false`. Good template for future pure-docs slices.

## What went well

The split call was right — SLICE-A is small, mechanically obvious, and the gates all came up green on first run. Skill cap math worked out (109+21=130, 92+13=105, both well under 200). Reviewer + deployer routing rows are precise enough to actually fire on the right signals without firing on everything (e.g. the silent-failure row is gated on "runnable change" specifically). The `## Rollback decision matrix` content is dense but operationally useful — a deployer under pressure can read the row + tie-breaker in 30 seconds and have a defensible call.

## What went wrong

First-round edits silently landed in the main repo instead of the worktree because the Edit tool was given main-repo absolute paths. Spotted at the AC verification step when `grep` returned 0 hits in the worktree files. Recovery was clean (`git checkout --` in main, re-apply in worktree with correct paths), but it's a class of error that's worth a memory entry — the harness session's working directory was correct but the Edit tool ignored CWD and went by the literal `file_path` argument.

## What I would do differently next time

When opening a slice inside a worktree session, deliberately resolve the worktree base path FIRST (e.g. `pwd` + capture into a variable / scratchpad note) and prefix every Edit `file_path` argument from that base. Avoid pasting absolute paths from earlier turns of the chat — those were captured in the main repo's directory and silently misdirect Edit when the session moves into a worktree.
