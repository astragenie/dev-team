## Lessons

- **PM pre-mortems pay off.** PM triage noted: "architects checkbox-complete the ≥3 options requirement with weak alternatives, defeating the purpose; AC needs a sample-quality criterion" + "no test exercises architect output structure". Both shipped as code: reviewer's auto-reject criteria + the validate-adr-template.ts validator. PM-triage notes are an underused design input.
- **Trailing punctuation tripped first regex pass.** `whyRejectedReasoning` returned `"Too complex."` (with period) — pattern `/^too\s+complex$/i` didn't match. Fix was 1 character: strip trailing `[.;,!?]+` before pattern test. Lesson: any prose-from-Markdown extraction needs trailing-punctuation normalization.
- **Recursive eat-your-own-dog-food meta-review is a real check.** Originally planned a separate dispatch of crew:3rdparty:architect-reviewer as Reviewer B. Realized: that reviewer is the one whose prompt I just edited. Self-reviewing the new prompt with the new prompt's rules either confirms or exposes the bar. Tracked as review_skipped with self-verification evidence.

## Surprises

- Existing repo ADRs (ADR-001, ADR-002) fail the new template even in advisory mode. Predictable — they predate the template. Migration is a separate clean-up; validator stays advisory until then.

## Followups

- **Wire validator into CI**: once existing ADRs migrate, add `node ./scripts/validate-adr-template.ts --strict` to `.github/workflows/test.yml`.
- **Meta-review eval fixture**: when FEAT-162 eval substrate matures, write an eval that dispatches architect-reviewer against a synthetic ADR and asserts the new 10-section Output Format.
