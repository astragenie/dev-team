## Lessons

- The gepa-core LLMJudge interface's own JSDoc explicitly states context "MUST NOT be dropped" — and 4 of 7 call sites (the validate_with path plus 3 of 7 provider adapters) violated that contract on first implementation. This is a strong argument for a contract-conformance test (assert every adapter's `evaluate()` references `opts.context`) rather than relying on manual per-adapter review each time a new provider is added.
- AC-3's deferral (no pre-refactor baseline to diff against) is carried forward and later resolved by a dedicated cross-slice artifact (see `validations/20260629T125000Z-ac4-live-baseline-slice107-slice108.md`), which explicitly ties SLICE-107's AC-3 and SLICE-108's AC-4 together as "the same operator gate."

## What went well

A real regression (context-dropping on 4 of 7 evaluate() call paths, violating the upstream interface's explicit contract) was caught by review before merge, fixed, and independently re-confirmed by the validator with specific line citations rather than a rubber-stamp re-check.

## What went wrong

The initial implementation shipped 4 call sites that silently violated a documented interface contract ("MUST NOT be dropped") — this is exactly the kind of defect that, had the review process not existed, would have caused silent Langfuse observability loss in a production deployment with real API keys configured.

## What I would do differently next time

Add an automated conformance test the moment a new external interface contract is adopted (here: "every `evaluate()` implementation must reference `opts.context`") rather than relying on a manual reviewer grep to catch violations of a documented MUST-NOT rule.
