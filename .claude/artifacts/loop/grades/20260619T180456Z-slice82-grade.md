## Decisions

### DEC-TBD-1: `${env:VAR}` and `${env:VAR:-default}` opt-in markers for workflow YAML env substitution

**Rationale**: Considered bare `${VAR}` (POSIX-shell-style) and `$VAR` (Make-style). Both have false-positive risks — any value containing a literal `$` followed by an identifier would silently capture. `${env:VAR}` requires the explicit `env:` namespace + braces, making accidental capture nearly impossible. The `${env:VAR:-default}` form matches POSIX `${VAR:-default}` semantics for fallback. Values-only (not keys); no embedded interpolation.

**Consequences**:
- positive: zero false-positive substitutions; explicit + grep-able marker.
- positive: aligned with POSIX fallback semantics so it reads naturally.
- positive: typed `EnvSubstitutionError` with `.variable` field gives clear error message on missing env var.
- negative: more verbose than bare `${VAR}`; users familiar with Helm-style templates may grumble.
- negative: future Bash-style or Make-style interpolation styles cannot be added without breaking change.
