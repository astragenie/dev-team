# SLICE-16: TS Migration Phase 0 Foundation — Grade

**Slice:** SLICE-16

## Scores

- architecture_quality: 0.85 — Clean Result<T,E> + branded types + Zod boundary schema; checkJs:false / migrate-first approach is correct. Small deduction: allowImportingTsExtensions needed late fix.
- reliability: 0.88 — 414 tests pass, live-file schema test validates real workflow-state.json, all CI gates green.
- observability: 0.75 — Baseline doc captured; no runtime observability improvement (tooling-only slice).
- production_readiness: 0.85 — CI on Node 22, advisory typegraph gate, README + CLAUDE.md updated.
- security: 0.80 — Zod validation at JSON boundary reduces parse-and-assume risk on workflow-state.json.
- test_confidence: 0.90 — TDD approach; 3 new test files, live-file fixture test, ≥4 cases per module.
- product_completeness: 0.88 — All 12 ACs satisfied. requires_validation waived (pure tooling, no user-visible behavior change).

## Lessons

- `allowImportingTsExtensions: true` required when importing `.ts` by extension with `--experimental-strip-types`; include in tsconfig template for future TS phases.
- Live-file schema test (AC-5) is high-value: catches schema drift vs. real data immediately.
- `costStopThreshold` needs to be raised when historical slices were Opus-heavy; the default (1 HIGH = stop) is too sensitive for catching up after model-switch.

## Decisions

### DEC-TBD: checkJs:false for migrate-first TS adoption

**Rationale**: Setting `checkJs: false` means existing `.mjs` files are not type-checked until renamed. This avoids mass churn before Phase 1 and keeps CI green immediately.

**Consequences**:
- Faster Phase 0 land without touching 11k LoC of existing `.mjs`
- `.mjs` files have no type safety until explicitly migrated (acceptable: they had none before)

### DEC-TBD: requires_validation:false waiver for tooling slices

**Rationale**: Phase 0 adds tooling infrastructure only (tsconfig, 3 small modules, CI config). No user-visible behavior changed. Test suite (414 pass) is the adequate validation signal.

**Consequences**:
- Loop slice close does not require a separate validation artifact for pure-tooling slices
- Pattern documented for future mechanical/tooling slices

## Surprises

- Node v24.16.0 is already installed (≫ 22.6 minimum), no upgrade needed.
- `--experimental-strip-types` works transparently with existing `.mjs` test files — no interference.

## Followups

- Phase 1: Start leaf-up `.mjs` → `.ts` migration; begin with `scripts/lib/` modules that have fewest dependents.
- Add `@typescript-eslint` flat-config plugin in Phase 1 once first `.ts` source file is under enforcement.
- Expand `WorkflowStateSchema` in schemas.ts as subsequent phases add JSON-on-disk boundaries.
