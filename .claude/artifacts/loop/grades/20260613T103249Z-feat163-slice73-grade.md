## Lessons

- Builder detected a DAG cycle DURING implementation (FEAT-163 spec line 43 listed `architect → document-writer`, but SLICE-71 had given `document-writer → architect`). Cycle resolution required removing one edge — builder chose to drop the spec-listed edge unilaterally. Should have surfaced as a needs_fix or required a DEC before landing.
- Validator silently passes when `tools:` is in inline YAML array format (`tools: [Read, Grep, Agent]`) — only the block list format triggers the lint rule. 2 of 4 SLICE-73 agents (architect, uxdesigner) use inline format; their Peer dispatch sections are NOT enforced by the rule yet. Inspector caught this.
- New validator `validate-dispatch-graph.ts` works (6 nodes, clean DAG output). CI gate is BLOCKING (no continue-on-error per FEAT-163 risk #2).

## Decisions

### DEC-022: architect → document-writer edge dropped to preserve DAG

**Rationale**: FEAT-163 line 43 listed `document-writer` in architect's whitelist. SLICE-71 gave `document-writer → architect`. Adding the reverse edge in SLICE-73 closes a cycle. Cycle detector (validate-dispatch-graph.ts) would have hard-failed. Builder removed `document-writer` from architect's whitelist. Architect→docs handoffs now go via lead-mediated dispatch (existing pattern). Spec amendment needed in FEAT-163 body to reflect this.

**Consequences**:
- positive: DAG preserved; cycle detector exits 0 with 6 clean nodes
- positive: no implementation surprise — architect already worked without direct docs dispatch
- negative: FEAT-163 spec line 43 now incorrect; needs amendment in SLICE-74 (or via spec-writer pass)
- negative: minor capability loss — architect can't directly hand off to document-writer without lead

## Surprises

- The cycle was latent for ~2 hours after SLICE-71 landed; only surfaced when SLICE-73 tried to close the loop. Cycle detector caught it during builder implementation, not during SLICE-71's review.
- `qa-expert ↔ performance-engineer` bidirectional pair encoded as `BIDIRECTIONAL_ALLOWED` constant — both single-edge whitelists actually show only `investigator` in the validate-dispatch-graph output, suggesting the bidirectional edges were NOT actually written to the agent prompts. Verify in SLICE-74 — either fix the prompts to include the pair, or remove the BIDIRECTIONAL_ALLOWED entry as moot.
