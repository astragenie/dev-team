## Decisions

### DEC-026: Slim-down targets measured against preserved-section floor

**Rationale**: When proposing a line cap for an agent/skill slim-down slice, the spec-writer MUST sum the preserved-section line ranges first and set the cap at that floor + reasonable headroom (≤15%). Setting caps relative to "desired reduction" without measuring the floor produces unreachable targets that get amended mid-slice and erode product_completeness scoring. The FEAT-158 "≤200" target was set against stale 278-line count when current was 369, and the irreducible preserved sections alone are ~290 lines.

**Consequences**:
- positive: slice AC stays achievable; no mid-slice amendments needed; reviewers can hold the line.
- positive: surfaces "what's irreducible" as an explicit early decision (which sections are identity-defining vs relocatable).
- negative: requires spec-writer to do upfront line-counting (cheap; one Bash command).
- negative: aspirational targets get traded for measured floors — caller may push back on "why not 200?". Answer is now "because the floor is N + 15%".

## What I would do differently next time

Add a `## Preserved sections floor` block to the spec-writer template — line-count each preserved section before proposing the slim-down cap. Output: `floor = sum(preserved_ranges) + 15% headroom`. Caps proposed below the floor are silently bumped to the floor. Optional: emit a warning in the spec when the FEAT description's target line count is below the measured floor.

Move the "did this slice's AC text actually match the realized state?" check into the CHANGELOG step of the slice-close ceremony. Inspector caught the "369 → ≤200" inconsistency because they happened to diff the CHANGELOG against the AC. Reading the CHANGELOG against the realized state before close is cheap and would have caught it without a reviewer round.
