# DEC-025: Executable canonical entry for domain skills

## Context

When a domain skill ships testable scan/audit/check behavior, the skill MUST cite an executable script as the canonical entry (`scripts/<name>.ts`) and the integration test MUST invoke that script directly. Procedural skills (Markdown-only prose describing commands a human or test inlines) duplicate logic between skill body and test, drifting over time. The `security-advisory/SKILL.md` Python orphan reference is the cautionary tale.

## Consequences

### Positive

- positive: one source of truth for skill behavior; test asserts the actual entry point.
- positive: typescript-reviewer gets a real review target with proper type safety + exit code semantics.
- negative: +~80 lines per new skill that ships a script; +1 file in the directory layout.
- negative: skills that are purely procedural advisory (e.g. checklist of what to verify by hand) do NOT need a script — judgment call lives with the skill author.
