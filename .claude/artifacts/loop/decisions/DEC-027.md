# DEC-027: Default mode for executable analyzer skills = PR-review (--changed-only)

## Context

When a domain/workflow skill ships an executable analyzer (regex scan, AST check, security sweep, test-quality lens), the DEFAULT invocation mode must be PR-review (--changed-only --diff-base ref), not bulk audit. PR-review mode is the consumer most-frequent use case — a reviewer running the lens on a slice diff. Bulk audit is opt-in via a --bulk flag for explicit full-tree sweeps. Default-bulk produces noise that reviewers learn to ignore; default-PR-review produces precise signal at the cost the consumer expects. Applies to: security-sweep, test-quality, any future regex-based analyzer skill.

## Consequences

### Positive

- positive: lens output stays signal-rich on the most-common invocation path.
- positive: bulk-audit noise is bounded to intentional sweeps where the consumer chose the wider scope.
- positive: integration tests against fixtures need to pass --bulk explicitly — a tiny extra arg in exchange for honest default semantics.
- negative: consumers who invoke the analyzer for the first time without reading the README get 0 findings on a clean diff. Acceptable: SKILL.md explicitly documents the default; the --bulk flag is named for discoverability.
- negative: requires a --bulk flag to be added to security-sweep too (currently it defaults to bulk-scan-only). Follow-up: SLICE-69 security-sweep should follow this same pattern in a v2.
