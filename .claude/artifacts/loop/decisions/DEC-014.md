# DEC-014: Validator owns the mandatory full gate; builders run affected-class tests only

## Context

Slice build time was dominated by the full quality gate running up to **three
times per slice**: `builder-be`, `builder-fe`, and `builder` each ran whole-repo
`npm run lint`, `format:check`, `typecheck`, and the **complete** test suite in
their self-verify gate. The full suite is the slowest part of a slice and most
of those runs were redundant — the same repo, the same suite, three times.

FEAT-030 had let the reviewer bundle a `--validation-evidence` note so the lead
could skip the validator on tests-already-green code-only diffs. That skip was
predicated on the builder having already run the full suite — an assumption this
change invalidates.

## Decision

Rebalance the gates:

- **Builders run a scoped fast inner loop** — `typecheck` + **affected-class
  tests only** (per-stack native: `node --test` on colocated siblings,
  `vitest related`, `dotnet test --filter`, `pytest <files>`). They no longer
  run whole-repo lint, `format:check`, or the full suite. Each handoff names the
  affected set under `## Deferred to validator`.
- **The validator owns the single mandatory full gate** — whole-repo lint,
  `format:check` (check-only; the read-only validator bounces formatting fixes
  to the builder), the complete test suite, and `validate-all` — run first,
  **every** code-bearing slice. There is no skip path, even for code-only diffs.
- **The reviewer re-runs the builder's affected set** as a backstop against
  over-narrow scoping, and may be fanned out across review lenses.

This supersedes the FEAT-030 reviewer-bundled-validation skip. The
`--validation-evidence` CLI flag on `write-review-result` remains for
back-compat but is no longer emitted by `reviewer.md` or consulted by the lead.

## Consequences

### Positive

- Full suite runs **once** per slice instead of up to three times.
- Builder turnaround drops from full-suite to affected-tests (seconds vs minutes).
- One always-on home for the full gate closes the FEAT-030 code-only coverage
  gap that the scoped builders would otherwise have opened.

### Negative

- The validator now runs on **every** code-bearing slice (was skippable),
  adding one dispatch where the old skip path applied.
- Affected-test scoping can miss a regression in an untouched file that depends
  on a changed one; the reviewer's affected-set re-run and the validator's full
  suite are the two backstops.

### Neutral

- `format:check` in the validator is check-only (read-only agent); a formatting
  failure becomes a `failed` validation that bounces to the builder rather than
  being auto-fixed in place.

## Alternatives considered

- **Put the full gate on the reviewer instead of the validator** — rejected:
  the user chose the validator as the mandatory final gate; the reviewer fans
  out across lenses and should stay focused on the diff, not own suite execution.
- **Keep the FEAT-030 skip and have builders keep running the full suite** —
  rejected: that is the redundancy this change removes.
