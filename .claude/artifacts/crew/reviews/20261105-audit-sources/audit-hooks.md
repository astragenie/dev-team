# Audit: hooks/ runtime (dev-team / crew v0.67.0) -- read-only

## Measured
- Process counts (hooks/hooks.json): SubagentStop 5 (1 bash + 4 bun), SubagentStart 2, PreToolUse Bash 3, Agent 3, Read/Edit/Write/TaskUpdate 1, PowerShell 1.
- PostToolUse: Read/Agent/Bash/Edit/Write 3 each; every other tool (Grep, Glob, MCP, WebFetch...) 2 (otel + checkpoint).
- A normal Bash call = 6 bun spawns (3 pre + 3 post); Read = 4; Edit/Write = 4. They run in parallel, so wall time ~ slowest, process/CPU cost = sum.
- tests/hook-cold-start-bench.test.ts on this Windows box: p50 213.7ms, p95 264.7ms (100 spawns, trivial hook, input "{}" so it early-exits). Repo comment claims floor ~88ms. The bench only measures check-redundant-read with an empty payload; real hooks load zod/yaml/features-service first.
- Ad-hoc 15-run timing of real hooks via the npm bun shim under contention from 3 other agents: 670-970ms each; `bun -e 0` baseline 604ms; log_event.sh 525ms. Noisy upper bound. Point: spawn cost dominates, hook logic is negligible.
- `bun test tests/hooks/ hook-feature-gating hook-error-events telemetry-hooks-json`: 69 pass / 0 fail, 23s.
- Side effect: my timing of log_event.sh appended ~10 "x" events to the gitignored .claude/logs/events.jsonl. No tracked file changed.

## Ranked findings
1. HIGH perf -- hooks/hooks.json:84-205. 4-6 separate bun processes per tool call, each re-reading .claude/crew.json and re-importing libs. Fix: single dispatcher per event (Structural #1).
2. HIGH correctness -- hooks/lib/bash-gate-timer-tap.ts:8-9 (`const _gateHandles = new Map`). Pre and Post run in different processes, so recordGateEnd never finds the handle; Bash gate telemetry is silently dead. dispatch-handle-store.ts already documents and solves this for dispatch timing with files. Fix: persist handle to .claude/state, or drop both hooks (2 of the 6 Bash spawns).
3. HIGH robustness -- hooks.json has no `timeout` on any command. A hang (stdin never closes, otel flush, spawnSync git in pre-push-verifier.ts:80) blocks the tool call until Claude Code's default. Fix: timeout 5-10s on every entry.
4. MED perf -- hooks/otel-post-tool-use.ts:18,41 and otel-subagent-stop.ts:20: `cachedSdk` module cache is dead code (fresh process per call). When telemetry is enabled, every tool call does NodeSDK init + OTLP POST + `await Promise.race([shutdown(), 1000ms])` (lines 49-52): up to +1s per PostToolUse if the collector is slow; refused connection to default localhost:3000 fails fast. Even when disabled it statically imports zod + yaml (scripts/lib/telemetry/config.ts:8-9) and reads telemetry.yaml on every call, because feature-flag-lite defaults otel-telemetry to true so it never short-circuits. Fix: check telemetry.yaml existence/enabled before importing config; spool locally and export in one batch at Stop.
5. MED security -- artifact-lock (hooks/lib/pre-tool-use-artifact-lock.ts:69-84,192) compares `normalizeLockPath(lockedPath) === repoRelativePath` case-sensitively. On Windows a differently-cased path to the same file is not matched (SUSPECTED, not exercised). Header says glob but it is exact match only. Paths outside cwd become `../..` and never match. Matcher covers only Write/Edit/MultiEdit/NotebookEdit; `sed -i`, `Set-Content`, `>` via Bash/PowerShell bypass entirely. Fix: lowercase on win32, realpath, glob support, Bash/PowerShell write-target heuristic or document as advisory.
6. MED bypass -- hooks/pre-push-verifier.ts:56-58 `isPushCommand` = /\bgit\s+push\b/ or /\bgh\s+pr\s+create\b/. Bypasses: `git -C dir push`, `git -c k=v push`, `git --no-pager push`, push via the PowerShell tool (hooks.json:111-119 wires only preflight-shell for PowerShell), aliases, `bash -c`, scripts. It is a Claude Bash hook, not a git pre-push hook, and default-OFF (features["push-verify"]). "PASS" = any .md in validations/ modified within the last hour with `decision: pass`; the agent can write that file itself (no signature). Fix: real .git/hooks/pre-push too; widen regex; wire PowerShell.
7. MED hygiene -- scripts/log_event.sh:10,24. One full stdin payload file per event, never pruned: 2075 files / 8.2MB in this repo already; payloads include last_assistant_message and task text (plaintext, no scrub). Fix: log event+session+agent only; payloads behind a flag; retention.
8. MED Windows -- scripts/log_event.sh needs bash, date, cat, mkdir, disown, so it runs only if Claude Code finds Git Bash. hooks.json:9 invokes the quoted script path as the command; under a PowerShell hook shell that is a string expression, not a call (SUSPECTED). The `( ... ) & disown` async write may be killed when the hook tree is reaped (SUSPECTED lost events). printf builds JSON with an unescaped project_dir, so a native `C:\...` CLAUDE_PROJECT_DIR would yield invalid JSON lines (observed paths here were forward-slash, fine locally). No jq, no /tmp usage found. Fix: port to the dispatcher.
9. MED duplicate wiring -- .claude/settings.json wires `bun ${PWD}/hooks/pre-tool-use-agent.ts`, model-enforce, check-subagent-return and .claude/hooks/log_event.sh etc. When the crew plugin is also installed (dogfooding) these run twice per event (SUSPECTED: double events.jsonl rows, double systemMessages). .claude/hooks/*.sh are gitignored/machine-local, so behavior differs per clone.
10. LOW correctness -- pre-tool-use-model-enforce (hooks/lib/model-routing-enforce.ts:191-198). With .claude/loop.json `modelRouting.enabled:false` (this repo) the presence check passes, resolveDispatchModel returns null, action "none": no-op, agent frontmatter model governs. Correct and safe, but still costs a bun spawn plus crew.json and loop.json reads on every Agent dispatch. The repo never verified `updatedInput` is honored for the Agent tool (lib header lines 94-109); the systemMessage fallback only warns. Commands pass `model:` explicitly, so the hook is mostly redundant.
11. LOW -- legacy output shape: PreToolUse hooks return `{decision:"block"|"approve"}` (pre-push-verifier.ts:288, artifact-lock lib:245, check-redundant-read lib:124). Current Claude Code prefers `hookSpecificOutput.permissionDecision: "deny"|"allow"`; top-level decision is deprecated for PreToolUse. Works today; migration risk.
12. LOW race -- checkpoint-cadence lib:79 and cost-hygiene state.ts:29 read-modify-write `<session_id>.json` from parallel PostToolUse processes: lost updates, counts drift. session_id is interpolated into a path unsanitized (checkpoint-cadence lib:30, state.ts:29); input comes from Claude Code so exploitability is low; dispatch-handle-store.ts:18 sanitizes correctly, copy that.
13. LOW stderr noise -- feature-flag-lite.ts and features-service.ts write `[features] name: enabled|disabled` to stderr on every call, including the disabled path.
14. INFO fail-open/closed. Block-capable: gate-guard (SubagentStop, enabled:true in .claude/crew.json), artifact-lock (PreToolUse, enabled:true), builder-terminal-state and reviewer-decision (SubagentStop, default-on), dispatch-size (warn-first), pre-push-verifier (default off). All shims catch and exit 0 (fail-open on error). Wedge analysis: SubagentStop blockers honor `stop_hook_active` (gate-guard lib:166) so they block at most once; artifact-lock ignores expired (48h TTL) and malformed locks; a live stale lock blocks that one path up to 48h with "rm the lock file" as recovery. No hook can wedge a whole session. Feature flags are re-read from .claude/crew.json on every invocation (no cache; one small read per process).
15. INFO secrets: otel scrub (scrub.ts:12-26) denylists content/new_string/old_string/tool_response but not tool_input.command, file_path or url, so Bash commands (inline tokens, curl headers) are exported as span attributes (capped 2048 chars) when telemetry is enabled. Hook libs log only reasons/paths to events.jsonl, not file contents. No shell command is built from tool_input anywhere (spawnSync uses an argv array in pre-push-verifier.ts:80), so no shell injection found. cd-path parsing in resolveCommandCwd feeds `git -C` only.
16. INFO observability of hooks: hook-error.ts appends `type:"hook_error"` to .claude/logs/events.jsonl (different schema from log_event.sh rows: no schemaVersion/source/event) and exits 0. Failures are recorded but never surfaced to the user (no systemMessage); relies on the brief-me hook-health collector. logHookError swallows its own errors and uses process.cwd(), not payload cwd.
17. INFO dead hooks: none. All 22 hooks/*.ts are referenced in hooks.json and every referenced file exists. plugin.json has no "hooks" key; hooks/hooks.json at plugin root is the auto-loaded default path and the shape matches spec; ${CLAUDE_PLUGIN_ROOT} used correctly.
18. INFO docs/observability/ holds only agent-stats.md and langfuse-bridge.md. Default endpoint http://localhost:3000/api/public/otel/v1/traces, auth from env LANGFUSE_AUTH_B64.

## Structural improvements (drastic)
1. Single dispatcher per event: one hooks/dispatch.ts <Event> reads stdin once, crew.json once, switches on tool_name, calls the existing lib/ run*Hook functions in-process (shim/lib split already exists), merges outputs. Bash call 6 spawns -> 2 (pre+post); SubagentStop 5 -> 1-2. About 3-5x less process churn; on Windows each spawn is 100-200ms CPU plus antivirus scanning.
2. Delete or merge low-value hooks: bash-gate pair (dead, finding 2), model-enforce (redundant), record-read-content + check-redundant-read (merge), checkpoint-cadence (scope matcher to Edit|Write|Bash). The matcher-less PostToolUse entry with 2 hooks is the biggest waste (every Grep/Glob/MCP call).
3. Out-of-band telemetry: PostToolUse appends one line to a local spool; one Stop/SessionEnd step batches and exports OTLP with a hard 2s cap. Removes SDK init and the 1s flush from the hot path and the zod/yaml import tax.
4. Replace bash log_event.sh with the dispatcher: cross-platform, JSON.stringify, scrubbed, retention for payloads, no Git Bash dependency.
5. Make enforcement real: timeout on every hook, migrate to permissionDecision, Bash/PowerShell write-target detection for artifact-lock, a true git pre-push hook for push-verify, mtime-cached crew.json. Optionally `bun build --compile` the dispatcher (startup floor ~50-90ms remains).
